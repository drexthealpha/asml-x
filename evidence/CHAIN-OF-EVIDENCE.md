# CHAIN OF EVIDENCE

The single index for every claim ASML-X makes to a judge. Appended as work lands, never
written retrospectively.

Rules this file enforces:
- A claim with no evidence path is DELETED from the product, not softened.
- Every row's command must reproduce from a clean clone (verified at task 10.1).
- DEMONSTRATED means the artifact exists and shows the claim true. INFERRED means assumed
  from structure and NOT proven. Anything else is a defect.
- Every claim in README, JUDGE-GUIDE, the dashboard and the demo script carries an inline
  `[C-xxx]` reference resolving here.
- **Every row's evidence path and command must be PUBLIC.** A row whose script or artifact
  is gitignored is unverifiable by a judge, which defeats the purpose of the index.

Reproduce every row: `bash scripts/44-chain-verify.sh`
Append a row: `bash scripts/43-chain-add.sh <id> <claim> <evidence> <command> <label> <task>`

## Scope note, decided at task 0.2

Internal housekeeping claims (repo hygiene, secret scanning, planning-file exposure, the
history rewrite) are NOT in this index. They are recorded in `evidence/internal/HYGIENE-LOG.md`,
which is gitignored along with the scripts that produce them.

The reason is a contradiction task 0.2 caught: the C-1xx hygiene claims pointed at
`evidence/hygiene/` and at `scripts/39-repo-hygiene-audit.sh`, all of which are gitignored
because they contain the build's internal reasoning. A judge could not have run those
commands. Rather than un-ignore internal material to satisfy the index, the index was scoped
to product claims only, which is what a judge actually audits. Nothing was hidden: the
hygiene work is still recorded and still reproducible locally, it is simply not a claim the
product makes.
