== A DEFECT THIS TASK FOUND ==

The transaction URL form was wrong, and it was wrong for the same reason the address form had been.

Task 11.1 loaded an ADDRESS url in a real browser and found:

  requested  https://www.oklink.com/x-layer/address/<addr>
  resolved   https://www.oklink.com/x-layer/evm/address/<addr>

and the manifest was built with the corrected address form. But the TRANSACTION form was left as
/x-layer/tx/<hash>, because fixing the address form felt like the whole lesson. Loading a real
transaction URL in the browser for this task showed:

  requested  https://www.oklink.com/x-layer/tx/0xb4785fbc...bcec6f
  resolved   https://www.oklink.com/x-layer/evm/tx/0xb4785fbc...bcec6f
  title      X Layer - EVM Transaction Hash 0xb478...bcec6f | Blockchain Explorer | OKLink

Both forms redirect, and `curl -L` follows both silently while reporting 200, so neither stale form
looks wrong from a shell. Only loading them in a browser exposes it. Both are now the post-redirect
form in the manifest.

The page was confirmed to render the real transaction: it shows the X Layer explorer chrome, a
"Transaction details" heading, and our hash 0xb4785fbc...
