# The no-data proof

Task 4.7. PASS condition: serve the UI where its data files do not resolve, and **zero numeric
values may render** while **every panel names its missing source**.

This is the strongest anti-fabrication check in the phase. A dashboard that degrades to zeros is
worse than one that crashes, because a zero is a number a reader believes.

## Method

```bash
cd ui-v2 && pnpm build
mkdir -p /home/zulab/nodata-check && cp -r dist/* /home/zulab/nodata-check/
rm -rf /home/zulab/nodata-check/data          # the data directory is DELETED, not emptied
cd /home/zulab/nodata-check && python3 -m http.server 4174 --bind 127.0.0.1
```

Confirmed at the transport level before looking at the page:

```
GET /                      -> 200
GET /data/journal.jsonl    -> 404
```

Then measured in the page rather than judged by eye, with the assertions run in the console:

```js
[...document.querySelectorAll('.num')].map(e => e.textContent.trim())   // every numeric cell
[...document.querySelectorAll('section')]                               // every panel
```

## Result

| assertion | result |
|---|---|
| numeric cells containing a digit | **1**, and it is `poll 4s`, the polling interval from `DATA_LIMITS`, a static configuration value rather than data |
| numeric cells rendering an em dash | 14 |
| top-bar metrics rendering an em dash | 11 of 11 |
| panels naming their missing source | **7 of 7** |
| panels rendering a plausible number | 0 |

The three source paths appear on screen exactly as the loader requested them:
`data/journal.jsonl`, `data/learned-state.json`, `data/deployments.json`.

The footer states the rule the code implements: "Every number on this screen is read from the
agent's own output files. No value is generated by the UI, and a missing source renders as an error
rather than a zero."

## Two defects this proof found, both fixed

Recording them because they are the interesting output. The first run of this check did NOT pass.

1. **Panel headers rendered counts of zero.** "0 decisions", "0 refusals", "0 of 0", "0 shown".
   Each was technically derived from an empty array, and each was a false statement about the
   agent: "0 refusals" beside an unreadable journal asserts the agent refused nothing. Fixed in
   `risk-panel.tsx`, `journal-panel.tsx` and `chain-panel.tsx`: when the source is in an error
   state, the header meta renders an em dash.

2. **One panel of seven did not name its source.** The evidence panel showed a neutral "Waiting for
   a decision to be selected", which reads like a normal state rather than a missing file. Fixed by
   passing the journal's load error into it, so it names `data/journal.jsonl` like the rest.

Both are the same defect at different sizes: a UI reporting a plausible state while its input is
absent. That is precisely what this task exists to catch, and it caught them.

## How the code makes this structural rather than careful

`ui-v2/src/lib/data.ts` returns a tagged union: `loading`, `ok` with a value, or `error` with the
source and the reason. There is no default value anywhere in the file, so a panel cannot accidentally
render a zero: it has nothing to render but the error. Two extra guards live in the loader:

- A response whose body starts with `<!doctype` or `<html>` is treated as an ERROR, not parsed.
  A dev server that serves `index.html` for a missing file is the classic way a UI ends up
  "successfully" showing nothing.
- A journal whose every line fails to parse is an error naming the line count, not an empty list.
