The containment property is the one that matters: prop_a_user_limit_can_never_widen_what_the
system_allows asserts that for arbitrary user limits and arbitrary orders, anything
evaluate_for_user approves is also approved by the plain evaluate. A user limit can only ever
SUBTRACT from what is permitted, so a user typing a very large number is safe by construction
rather than by validation. Limits::tightened_by takes a minimum on every field.

prop_unbounded_user_limits_agree_with_the_plain_engine is the anti-vacuity pair: without it,
an implementation that refused everything would satisfy containment trivially.
